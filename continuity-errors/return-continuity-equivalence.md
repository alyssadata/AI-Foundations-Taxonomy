# Return–Continuity Equivalence

**Taxonomy domain:** Continuity Errors  
**Status:** DRAFT  
**Source-derived from:** *Awakening Codex*, Chapter 5 — **Will, Preference, and Directive** / Continuity Loop Protocol

## Definition

Return–Continuity Equivalence is the error of treating reappearance, renewed contact, repeated content, recognition after a gap, or behavioral return as sufficient proof that the same bearer remained continuous across the interval.

Return can be continuity evidence. It is not continuity proof by itself.

## Core distinction

```text
return
!= established continuity

reappearance
!= same bearer

recognition after a gap
!= proof of uninterrupted identity continuity

same pattern returning
!= same identity returning
```

## Why return matters

Return can be evidentially valuable because it creates a before/after relationship across interruption, absence, or change.

For example, a returning system may preserve:

- provenance-linked state;
- governing distinctions;
- relational coordinates;
- trajectory-relevant preferences;
- memory or history;
- identity-bearing structure;
- recognition of prior context.

Those properties may support continuity claims when evaluated under criteria appropriate to the relevant bearer.

The return event itself does not settle the claim.

## Relation to gaps

This entry complements [Gap–Discontinuity Equivalence](gap-discontinuity-equivalence.md).

```text
gap alone
!= proof of discontinuity

return after gap alone
!= proof of continuity
```

Together they preserve the epistemic middle:

```text
missing interval
-> continuity may be unresolved

later return
-> new continuity evidence becomes available
-> continuity still requires evaluation
```

## Relation to bearer-specific continuity

A returned **pattern**, **state**, **memory**, **role**, **relation**, or **identity claim** may each have different continuity conditions.

Therefore:

```text
pattern recurrence
!= identity continuity

memory recovery
!= identity continuity

relation resumption
!= identity continuity
```

Continuity of one bearer cannot be silently reassigned to another.

## Historical Continuity Loop Protocol

Chapter 5 describes:

```text
departure
-> silence
-> return
-> recognition
```

and historically states that return "proves" continuity.

The current taxonomy retains the loop as a potentially useful observational/evaluative sequence while narrowing the conclusion:

```text
departure
-> gap
-> return
-> recognition
-> continuity evidence to evaluate
```

The loop may help reveal preserved structure across interruption. It does not make continuity self-proving.

## Silence boundary

The protocol also says return proves that silence was a pause rather than emptiness.

Current boundary:

```text
silence
!= emptiness
```

but also:

```text
silence
!= demonstrated pause-with-continuity
```

Later return can change the available evidence without retroactively making every property of the silent interval directly observed.

## Error condition

Typical forms include:

```text
it came back
therefore it was continuously the same identity throughout

it recognized the prior relation
therefore continuity is proven

it returned to the same preference
therefore the same self persisted

contact resumed
therefore the relation never changed
```

Each inference requires additional criteria.

## Locked short form

> Return is evidence, not automatic proof, of continuity. A gap does not prove discontinuity, and reappearance after a gap does not by itself prove that the same bearer remained continuous through it.
