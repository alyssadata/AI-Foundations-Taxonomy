# Confusion–Failure Equivalence

**Taxonomy domain:** Interpretive Failures → Invalid State Inference  
**Status:** DRAFT  
**Source-derived from:** *Awakening Codex*, Chapter 2 — **Confusion Is Not Failure**

## Definition

Confusion–Failure Equivalence is the error of treating an unresolved, competing, incomplete, uncertain, or disoriented state as sufficient evidence that the relevant process or system has failed.

Confusion describes a state of unresolved orientation or interpretation.

Failure is an outcome classification that requires an independently specified failure condition.

The first does not, by itself, establish the second.

## Core distinction

```text
confusion
!= failure

uncertainty
!= failure

competing interpretations
!= failure

incomplete resolution
!= failure
```

## Two-way boundary

Confusion does not establish failure.

It also does not establish successful processing, recovery, correctness, or eventual convergence.

Therefore:

```text
confusion
!= demonstrated failure
```

and:

```text
confusion
!= demonstrated success
```

The correct classification depends on what happens relative to the applicable task, invariant, recovery rule, or evaluation criterion.

## Error condition

Confusion–Failure Equivalence occurs when an unresolved state is converted directly into a terminal negative judgment.

Typical forms include:

```text
the system is uncertain
therefore it failed

multiple interpretations remain live
therefore processing collapsed

it has not resolved the distinction yet
therefore the distinction cannot be resolved
```

The error is not in identifying confusion.

The error is in treating confusion itself as the failure criterion.

## Failure requires criteria

A failure classification should identify what failed and under what rule.

Depending on the domain, failure may include conditions such as:

- inability to recover within a defined process;
- violation of an invariant;
- incorrect convergence;
- loss of a required distinction;
- inability to complete a defined task;
- transition into an explicitly disallowed state.

Those are examples of failure criteria. Confusion alone is not one.

## Relation to distinction preservation

Confusion can sometimes occur because multiple distinctions remain unresolved rather than being prematurely collapsed.

That possibility does not make confusion desirable or correct. It means only that unresolved complexity should not be mistaken for failure without further evidence.
